```text

│   ├── Tools/                   ← 검사·추출·생성·배포 소스
│   ├── Docs/기획자 데이터 작성과 배포 가이드.md     ← 기획자 가이드
│   ├── DeployData.exe          ← 설치 없이 사용하는 실행 도구
│   └── DeployData.cmd          ← 실행파일 호출 배치
└── Human_Ghost-/
    └── Assets/
        ├── Data/Csv/
        ├── Data/Json/
        └── 3.Script/Data/
            └── Generated/GeneratedDataLoadPlan.cs
```

| 출력 | DataSheet 기준 상대 경로 | 갱신 정책 |
| --- | --- | --- |
| CSV | `../Human_Ghost-/Assets/Data/Csv` | 매번 갱신 |
| JSON | `../Human_Ghost-/Assets/Data/Json` | 매번 갱신 |
| 일반 정의 C# | `../Human_Ghost-/Assets/3.Script/Data` | 파일이 없을 때만 최초 추가 |
| 생성 enum | `../Human_Ghost-/Assets/3.Script/Data/Generated/Enums`와 기존 StateKey.cs | 매 배포 갱신 |
| 자동 로딩 계획 | `../Human_Ghost-/Assets/3.Script/Data/Generated/GeneratedDataLoadPlan.cs` | 매번 갱신 |

기존 일반 정의 클래스는 덮어쓰거나 자동 삭제하지 않습니다. 기존 컬럼·생성자 변경은 개발자가 해당 클래스에도 반영합니다. enum은 원본 시트에서 매번 갱신하므로 직접 수정하지 않습니다. 자동 로딩 계획도 수동 수정하지 않습니다. 삭제한 탭은 다음 계획에서 빠지고 이전 배포 데이터와 생성기 소유 enum은 정리합니다. 갱신 파일의 Unity 메타는 유지합니다.

클라이언트의 `.datasheet-generated.json`은 도구가 관리하는 배포 파일 목록입니다. 수동 파일 보호와 이전 배포 정리에 사용합니다. 이전 스크립트 경로의 목록은 새 `3.Script` 경로로 해석합니다.

```mermaid
flowchart LR
```

`tables` 아래 새 xlsx와 새 탭을 자동 탐색합니다. 탭 이름은 전체 파일에서 유일해야 하며 클래스명으로 사용할 수 있는 영문 식별자를 사용합니다. 컬럼별 타입은 B1에 명시하고 값으로 추측하지 않습니다. ID는 기본적으로 필수 양의 정수·중복 금지이며 그룹 키는 필수 정수입니다.

현재 입력은 정수·문자열·Y/N 플래그와 선택 값입니다. 지원 규칙의 정확한 표기와 예시는 [기획자 가이드](Docs/%EA%B8%B0%ED%9A%8D%EC%9E%90%20%EB%8D%B0%EC%9D%B4%ED%84%B0%20%EC%9E%91%EC%84%B1%EA%B3%BC%20%EB%B0%B0%ED%8F%AC%20%EA%B0%80%EC%9D%B4%EB%93%9C.md)를 따릅니다.

## 데이터 정의와 상속

```mermaid
classDiagram
    CharacterStat <|-- UnitStat

    CharacterStat <|-- Elite
    Boss o-- BossState

    }
```

공통 스탯은 기반 클래스에 한 번만 선언합니다. Player·Monster는 공통 정의와 고유 컬럼을 연결하고, Boss·Elite는 공통 정의와 상태 목록을 조합합니다. 여러 BossState 페이즈 행은 한 보스의 상태 배열입니다.

| 현재 출력 | 내용 |
| --- | --- |
| CSV 13개 | Buff, Cutscene, CutsceneStep, HealthDisplayConfig, Language, Monster, Player, Popup, Skill, Stage, StageLayer, State, UnitStat |
| JSON 4개 | Item, PlayerState, BossState, EliteState |
| 정의 C# 21개 | 탭별 17개와 CharacterStat, Boss, Elite, StateKey |
| 자동 로딩 계획 1개 | 현재 시트의 초기화 연결 |

Item은 배열로, 상태 데이터는 지정한 그룹 키별 States 배열로 출력합니다. 빈 상태 시트는 빈 배열입니다. 클라이언트 정의는 읽기 전용이며 현재 체력·상태 타이머 같은 가변 실행 상태와 분리합니다.

## 수치·문자 원칙

기본 수치는 32비트 정수, 시간은 밀리초, 확률 분모는 10000입니다. 확률값과 배율을 구분하고 각 필드의 단위를 따릅니다. CritDamage·Skill.Damage는 정수 추가 피해입니다. 이동은 시트의 타일×100 단위를 사용하며 엔진 변환은 클라이언트 책임입니다.

플래그는 원본·CSV에서 Y/N, JSON과 C#에서는 참·거짓 값입니다. 텍스트와 생성 코드는 UTF-8을 사용합니다. CSV는 바이트 순서 표시 없이 줄바꿈 문자 LF로 저장합니다. 설명·주석·로그·직접 작성한 오류 안내는 한글로 작성합니다.

## 임시 파일과 실패 처리

추출·컴파일 결과는 윈도우 임시 폴더에서 만들고 종료 시 정리합니다. DataSheet에 outputs·생성 데이터 복사본·bin·obj를 남기지 않습니다. 실행 도구인 EXE는 공유에 필요한 파일이므로 저장소에 둡니다.

검사 실패 시 기존 배포를 변경하지 않습니다. 배포 쓰기에 실패하면 기존 파일로 원복합니다. 원복까지 실패했을 때만 필요한 복구 자료를 임시 폴더에 보존하고 위치를 안내합니다. 복구 자료는 문제 해결 전 임의로 삭제하지 않습니다.

## 개발자: 실행파일 갱신과 검사

```mermaid
flowchart LR

    B --> C[현재 시트·자동 계획 검사]
```

실행파일을 만드는 개발 PC에만 .NET 10 SDK와 최초 패키지 다운로드가 필요합니다.

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File Tools/Publish-DataExport.ps1
```

회귀 검사 도구는 다음 명령으로 실행합니다. 새 파일/탭 자동 로딩과 식별자 조회도 검사합니다. 이번 전체 점검은 EXE --check를 실행한 범위이며 이 회귀 명령을 새로 실행한 결과로 표기하지 않습니다.

```powershell
dotnet run --project Tools/DataExporter.Checks
```

생성 코드와 클라이언트 연결은 내장 컴파일러로 검사하므로 배포 EXE가 외부 dotnet을 실행하지 않습니다. 도구 소스를 바꾸면 EXE도 다시 만들어 함께 공유합니다. 데이터 값만 수정할 때는 EXE 재생성이 필요하지 않습니다.

## 보류·추가 확인

버프 실제 효과, 스폰 JSON 원본·생성, 몬스터 풀링 원본은 이후 작업입니다. `stats/item`은 예시이며 공식 배포 대상이 아닙니다. 보류된 파일의 존재를 요구하지 않습니다.

빈 시트의 참조 규칙 자체를 검사하는 보완은 남아 있습니다. 현재 데이터 검사 통과와 모든 미래 규칙의 검증을 동일하게 보지 않습니다.

2026-11-03 점검에서는 EXE --check의17탭·정의21·계획1과 클라이언트 데이터875·코어462, Unity 참조 컴파일 경고0·오류0을 확인했습니다. 과거14탭·정의18·CS0649 실패 기록을 현재 결과로 사용하지 않습니다. 실제 Unity Play·완주·출시 실행파일은 이번 점검에서 재검증하지 않았습니다.

기존 정의 보존 정책은 유지합니다. 현재 호환성 검사는 컴파일 중심이므로 시트 구조와 실제 정의 생성자의 차이를 명시적으로 비교하는 보완이 필요합니다. 빈 시트의 참조 규칙 검사와 함께 다음 개선 대상으로 기록합니다. 기존 정의 자동 덮어쓰기나 별도 규칙 탭 추가는 이 보완의 전제가 아닙니다.

기존 앵커 Play 메뉴 검사는 사용자 직접 실행 통과 기록을 유지하며 현재 병합 상태에서 재실행한 결과는 아닙니다. 새 Host 수명·운영 씬·최종 화면·플레이어 빌드는 별도 확인 대상이고 씬 연결 보류도 유지합니다. 상세 설계 점검은 형제 클라이언트의 Docs/개발자용 설계문서/설계 기준 점검과 개선 방향.md를 따릅니다.

기획자 제어형 콘텐츠 잠금과 플레이어 해금은 컬럼·정의·배포와 ContentAccess 판단 코어까지 준비했습니다. 실제 맵 입장·스킬·아이템·몬스터 생성 적용은 미연결입니다. 기획자 잠금이 전체 콘텐츠에 대한 상위 제어이고, 플레이어 해금은 그중 필요한 콘텐츠에만 적용한다는 방향을 유지합니다.
