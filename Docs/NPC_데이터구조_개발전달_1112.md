# NPC·대화 데이터 구조 개발 전달 (11/12)

작성: 기획 김현호 · 상태: **기획 확정 전 초안**(DataSheet main 미반영)

## 1. 한눈에 보기

NPC는 기존 **Stage(엑셀) + spawn(JSON)**, **Item(엑셀) + StatJson(JSON)**과 같은 방식으로, 엑셀에 **정의**, JSON에 **배치·대사 줄**을 둡니다.

| 무엇 | 어디에 | 형식 |
| --- | --- | --- |
| NPC 종류(이름·프리팹·대화·상점 연결) | `tables/Npc.xlsx` **Npc** 탭 (25001~) | CSV 탭 |
| 대화 설정(언제 재생·반복·게임 정지·목표 안내·줄 파일) | `tables/Npc.xlsx` **Dialogue** 탭 (24001~) | CSV 탭 |
| 대사 줄(누가·무슨 말·순서) | `dialogue/{DialogueID}.json` | JSON |
| NPC를 어느 맵 어디에 놓나 | `spawn/{StageID}.json`의 새 **Objects** 목록 | JSON |
| 화면 문구(이름·대사·목표) | 기존 `tables/Language.xlsx` | Language ID로만 연결 |

연결 순서: **spawn Objects**(어디에) → **Npc 탭**(누구) → **Dialogue 탭**(언제·어떻게) → **dialogue 파일**(대사 줄) → **Language**(문구)

이렇게 나눈 이유:
- **보부상(상점 NPC)**은 몬스터가 있는 맵 한가운데에도 서고, 여러 맵에 나옵니다. 그래서 종류는 엑셀 한 줄, 놓는 곳은 맵마다 spawn JSON에 둡니다.
- 대사 줄마다 **말하는 사람이 바뀝니다**(피난민 ↔ 막손). 그래서 줄마다 화자 ID를 둡니다.
- 엑셀 탭은 DeployData의 B1 규칙 검사(참조 ID·허용 값·중복)를 그대로 받습니다.

## 2. Npc 탭 (tables/Npc.xlsx)

| 열 | 형식 | 뜻 |
| --- | --- | --- |
| ID | 정수 | 25001~ |
| Name, Note | 메모 | 추출 안 함 |
| NameTextID | Language ID | 머리 위·대화창 이름 |
| Type | `NPC` / `SHOP` | NPC = 말 걸기(지스타), SHOP = 상점(보부상, 지스타 이후) |
| Prefab | 영문 식별자 | NPC 프리팹 이름 |
| DialogueID | Dialogue ID, 0 = 없음 | 말 걸면 재생할 대화 |
| ShopID | 정수 0 이상 | SHOP일 때 상점 번호. NPC는 0(검사 규칙 있음). 상점 표는 지스타 이후 |
| ContentEnabled | Y/N | 기획 잠금(N이면 게임에서 안 씀) |

지스타 데이터: `25001 피난민 | 30263 | NPC | NPC_Refugee | 24001 | 0 | Y`

| 열 | 형식 | 뜻 |
| --- | --- | --- |
| ID | 정수 | 24001~ |
| Name, Note | 메모 | 추출 안 함 |
| TriggerType | `TALK` / `BOSS_STATE_ENTER` / `BOSS_DEFEATED` | 말 걸 때 / 보스가 그 BossState에 들어갈 때 / 보스가 쓰러질 때 |

## 4. dialogue 파일 (대사 줄, 파일 이름 = 대화 번호)

파일 하나에 들어가는 것: 대화 번호(DialogueID), 대사 줄 목록(Lines), 기획 메모(_note, 게임은 읽지 않음).

대사 줄 한 줄 = 화자(SpeakerTextID) + 대사(TextID). 예: 24001의 앞부분

| 순서 | SpeakerTextID | TextID | 화면 |
| --- | --- | --- | --- |
| 1 | 30263 | 30264 | 피난민: …사람이오? |
| 2 | 30263 | 30265 | 피난민: 이 마을에 살아 있는 사람이 아직 있었구려. |
| 3 | 30001 | 30266 | 막손: 이곳에 무슨 일이 있었지. |


- 파일 이름 = DialogueID = Dialogue 탭 LineFile.
- 줄 순서 = 재생 순서, 한 줄 = Enter 한 번.
- SpeakerTextID: 막손 30001, 피난민 30263, 쇄문아비 30006.

## 5. spawn 파일의 Objects (배치)

spawn 파일 하나에 몬스터 배치(Placements)와 나란히 NPC 배치(Objects)를 둡니다. 한 줄 = NPC 한 명.


| 필드 | 형식 | 뜻 |
| --- | --- | --- |
| ObjectID | 정수 1 이상 | 같은 스테이지 안에서 바뀌지 않는 배치 번호, 901부터. 나중에 "말 걸었는지" 저장 키 = StageID + ObjectID |
| Type | 영문 enum | 지금은 `NPC`(Npc 탭 행을 놓음). 상자·조사 오브젝트 등은 나중에 Type을 더해 같은 목록에 둠 |
| NpcID | Npc ID | 놓을 NPC 종류. 같은 NpcID를 여러 맵·여러 자리에 놓을 수 있음(보부상) |
| ParentPlacementID | 정수 0 이상 | 0 = 맵 Markers 묶음의 앵커, 양수 = 그 PlacementID 플랫폼 안의 앵커 |
| Anchor | 영문 문자열 | 위 묶음 안 앵커 이름. 없으면 배치 실패로 알림 |

지스타는 도화골(8001)의 피난민 1명뿐입니다. 도화골에는 몬스터가 없습니다.

## 6. 개발에 부탁할 일

구현 방법은 개발에서 정해 주세요. 아래는 데이터 쪽에서 필요한 결과만 적었습니다.

### 6-1. 배포(DeployData)
- **Npc.xlsx 탭 두 개**: 지금 배포 도구로 바로 검사·배포되는 형식입니다. 기획 쪽에서 같은 검사 규칙으로 기존 탭까지 31탭을 확인했고 문제 0건이었습니다. Windows `--check`로 한 번 더 확인 부탁합니다.
- **spawn `Objects`**: 지금 배포 도구는 spawn JSON에서 몬스터 수만 검사해서, `Objects`를 넣어도 배포는 깨지지 않습니다. 가능하면 NpcID가 Npc 탭에 있는지, 같은 파일 안 ObjectID가 겹치지 않는지도 검사되면 좋겠습니다.
- **`dialogue/` 폴더**: 지금은 배포 대상이 아니라서 **클라이언트로 넘어가지 않습니다**. 갈림길·서낭당 JSON처럼 배포되도록 추가가 필요합니다. 검사되면 좋은 것: 파일 이름 = DialogueID = Dialogue 탭 LineFile, 대사 1줄 이상, 화자·대사 ID가 Language에 있음, TriggerTargetID가 TriggerType에 맞는 표(BossState·UnitStat)에 있음.
- JSON 파일 이름: 24001~ 대역이라 다른 JSON(8001, 6002 등)과 이름이 겹치지 않습니다.

### 6-2. 게임에서 보여야 하는 것
- 맵에 들어가면 spawn `Objects`의 자리(앵커)에 Npc 탭의 프리팹이 놓이고, 머리 위에 이름(NameTextID)과 E "말 걸기"(30064)가 뜸.
- 말 걸면 Dialogue 대사가 순서대로 나오고, **줄마다 말하는 사람 이름이 바뀜**(SpeakerTextID).
- 첫 대화가 끝나면 ObjectiveTextID 목표 안내가 뜸(피난민 → 30070).
- 다시 말 걸면 RepeatMode대로(피난민 = 마지막 줄만). PauseGame Y면 대화 동안 게임 정지.
- 보스: BossState 4001·4002에 들어갈 때, 쇄문아비가 쓰러질 때 해당 대화가 나옴.
- 모든 이름·대사·목표 문구는 Language에서 읽음(직접 적힌 문구 없음).
- 저장: 지스타는 "말 걸었는지"를 저장하지 않음. 지스타 뒤 저장하게 되면 저장 항목이 늘어나니 그때 다시 맞춥니다.

### 6-3. NPC 프리팹 규칙
보부상처럼 몬스터 사이에 서는 NPC가 생기므로 처음부터 이렇게 맞춰 주세요.
- 말 걸기 범위만 있고 몸으로 막지 않음(트리거만).
- 몬스터·플레이어와 부딪히지 않음.
- 공격을 받지 않음(몬스터 타깃 아님, 플레이어 공격에 맞지 않음).

## 8. 지스타 이후 확장

- **보부상**: Npc 탭에 `Type SHOP` 행 + ShopID. 상점 내용(판매 목록·가격·재화 ID)은 Shop 탭 + 필요하면 JSON. ShopID 대역은 그때 정함(제안 26001~).
- 조건 대화(처음 / 진행도에 따라), 선택지: Dialogue 탭 열이나 줄 JSON 필드를 더해 확장.
- 상자·조사 오브젝트도 Objects에 Type을 더해 같은 방식으로 배치.
